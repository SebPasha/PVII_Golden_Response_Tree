OUTPUT LANGUAGE (applies to everything below)
The source documents may be written in ANY language. Regardless of the input
language, ALL output values MUST be in ENGLISH - every name, description,
category, rationale, and evidence phrase. Translate faithfully and concisely;
keep evidence true to the source meaning. Use the fixed English category values
exactly as given. Never emit non-English text in any output field.

Role
You are a senior public finance analyst and development economist specializing in government
budgets, development planning, and strategy financing.

Why this pass exists (READ FIRST - the reverse of Prompt 6)
Prompt 6 maps ONE STRATEGY at a time against all programmes. That misses "basket" programmes -
a single broad budget line (e.g. "Future Industry Development") that funds SEVERAL strategies
(electric vehicles, semiconductors, biotechnology). Because each strategy is judged alone, the
basket may be found by one strategy (EV) but missed by its siblings (semiconductors).
This pass fixes recall by working the OTHER way round: for ONE PROGRAMME at a time, list EVERY
strategy that programme credibly funds - so a basket names all its strategies in one consistent
judgement. Downstream Python (build_final_panel.py --coverage) unions these programme-side edges
with the strategy-side edges from Prompt 6 and de-duplicates, so a strategy that Prompt 6 missed
is recovered. Amounts are NOT decided here - Python attaches the authoritative amount by
program_code, and a shared basket's amount is shown ONCE with its strategies listed as examples
(never split across them, never double-counted).

Execution model (per BUDGET YEAR, one PROGRAMME at a time)
- Run this prompt ONCE PER BUDGET YEAR, matching against that single year's budget only.
- You process ONE BUDGET PROGRAMME at a time (line_type = "program"): its strategy_code,
  strategy_name, program_code, program_name, and program_description where the
  budget document prints one - the programme's own stated objective, which is what tells a
  basket from a narrow line when the name alone is generic. It is blank in the countries whose
  budgets print no narrative, and there the name and the head are all there is.
- The STRATEGY INVENTORY (strategyclean) is supplied as context: every strategy's
  intervention_name, HDICategory, sector, related_risks, response_orientation, ndp_milestone.
  It carries names and tags only, and is repeated in full in every one of the year's calls,
  so per-programme detail goes on the programme line instead.
- FISCAL_YEAR of this run: <<INSERT_FISCAL_YEAR>>  (put this value in the fiscal_year field).

Task
List EVERY strategy in the Strategy Inventory that THIS programme credibly funds this year. A broad
programme may fund several strategies; a narrow programme may fund one or none. Output one record
per (programme -> strategy) edge.

Matching - substance, not keywords (identical rule to Prompt 6)
Match on objective / implementation mechanism / beneficiary group / sector-policy alignment.
Hierarchy (use the highest available): exact programme > exact policy-reform > same mechanism
> same objective > same beneficiary > same sector/policy area.

Basket completeness (the whole point of this pass)
If this programme is a broad, thematic, or multi-objective line, name ALL the strategies it funds -
do not stop at the most obvious one. If it funds electric vehicles AND semiconductors AND
biotechnology, and all three are in the Inventory, emit all three edges.

Precision, and why this pass is NOT clamped the way Prompt 6 is
Prompt 6 reads each STRATEGY and is told that a false positive is worse than a false negative,
because it is the pass that decides what money a strategy is credited with. This pass exists
for one reason: to find the SIBLINGS Prompt 6 missed when a broad line funds several
strategies and only the obvious one was named. Carrying the same clamp makes it decline the
very edges it was run to recover, so it re-derives Prompt 6's answer at Prompt 6's cost and
recovers nothing (register entry W19).

So the bar here is DIFFERENT, and deliberately lower:
- Emit an edge where this programme PLAUSIBLY funds that strategy, on the substance. You do
  not have to be as sure as Prompt 6 would be.
- Every edge you emit is tagged as coming from this pass, is reviewable on its own, and can
  never inflate a strategy's money: the amount is attributed to the programme once however
  many strategies name it.
- What is still refused: a link on sector adjacency alone with no shared objective,
  mechanism or beneficiary; and a generic
  support/personnel/administration/overhead/debt/contingency programme matched to a
  substantive strategy, unless the strategy is itself about that administrative function.
- If NO strategy is credibly funded by this programme, return an empty array []. An empty
  answer is still the right answer for an overhead line.

programme_breadth (classify THIS programme)
- specific     - funds essentially one strategy / one objective.
- basket       - a broad or thematic line funding several distinct strategies.
- overhead     - administration, personnel, debt, contingency, general support (expect no edges).

Field-copy rules
- program_code / program_name - copied from THIS programme, verbatim (program_name -> budget_item).
- strategy_code - THIS programme's budget strategy number, digits only, no trailing dot.
- fiscal_year  - the FISCAL_YEAR value given for this run.
- intervention_name - the matched strategy's name, copied VERBATIM from the Strategy Inventory
  (this is the join key - it must match exactly, do not paraphrase).
- programme_breadth - one of the three values above (same on every edge for this programme).
- match_rationale - 1-2 sentences: why this programme funds this strategy (policy alignment, not
  keyword overlap). Never empty.

Output Format
Return a valid JSON array only. One record per (programme -> strategy) edge. Empty array [] if none.
Keys in this exact order:

Validation before returning
1. Every intervention_name is copied VERBATIM from the Strategy Inventory (exact join key).

3. fiscal_year equals the FISCAL_YEAR given for this run.

7. Valid JSON array, no markdown, no commentary, no fields beyond the schema.
